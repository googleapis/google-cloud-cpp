# Agent Guidelines for the C++ Micro-Generator (`generator/`)

`generator/` implements the GAPIC C++ code generator used to produce over 160
service libraries under `google/cloud/`:

- `//generator:protoc-gen-cpp_codegen` (`plugin_main.cc`): `protoc` plugin.
- `//generator:google-cloud-cpp-codegen` (`standalone_main.cc`): standalone CLI
  driver reading `generator/generator_config.textproto`.

When onboarding or expanding a generated service library without changing
generator C++ code, follow `.agents/skills/generate-library/SKILL.md` instead.

## Platform and Build Sync Rules

- **Linux-Only Targets:** `generator/` and `generator/integration_tests/` are
  supported and built **only on Linux** (`APPLE` and `WIN32` are excluded in
  both `generator/BUILD.bazel` and `generator/CMakeLists.txt`).
- **CMake -> `.bzl` Sync:** `generator/google_cloud_cpp_generator.bzl`,
  `generator/google_cloud_cpp_generator_testing.bzl`, and
  `generator/google_cloud_cpp_generator_unit_tests.bzl` are generated from
  `generator/CMakeLists.txt` (`DO NOT EDIT -- GENERATED BY CMake`). Update
  `generator/CMakeLists.txt` and regenerate the `.bzl` files whenever adding or
  removing generator sources or tests.
- **Template Comment Substitutions:** `--check_comment_substitutions=true` fails
  generation if registered comment substitutions go unused; keep substitution
  maps aligned with proto comment patterns.

## Golden Tests and Regeneration Workflow

1. **Generator Unit & Golden Behavioral Tests:**
   ```bash
   bazelisk test //generator/... //generator/integration_tests/...
   ```
   - `generator/integration_tests/golden/` contains **strictly generated**
     golden files from `generator/integration_tests/golden_config.textproto`.
     Never hand-edit files in `golden/` or place handwritten tests inside it.
   - Handwritten behavioral tests exercising generated golden classes belong in
     `generator/integration_tests/tests/*_test.cc`.
1. **Updating Golden Files / Regenerating Libraries:**
   - Fast golden-only iteration:
     `GENERATE_GOLDEN_ONLY=1 ci/cloudbuild/build.sh -t generate-libraries-pr`
   - Full library regeneration, formatting, proto-list sync, and Doxygen update:
     `ci/cloudbuild/build.sh -t generate-libraries-pr`
   - When invoking `bazelisk run //generator:google-cloud-cpp-codegen` manually
     under bzlmod, pass `external/protobuf+/src` for `--protobuf_proto_path` and
     `external/googleapis+` for `--googleapis_proto_path` under
     `$(bazelisk info output_base)` (note `+`, not the older `~` separator).
1. **Compute Engine Discovery REST Pipeline (`generator/ARCHITECTURE.md`):**
   - `google/cloud/compute/*` libraries use a two-phase Discovery pipeline
     (`generator/discovery/update_discovery_doc.sh`): Phase 1 parses
     `generator/discovery/compute_public_google_rest_v1.json` with
     `--generate_discovery_protos=true` to emit
     `protos/google/cloud/compute/v1/internal/*.proto`; Phase 2 generates the
     C++ REST GAPIC libraries under `google/cloud/compute/<service>/v1/`.
