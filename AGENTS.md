# Agent Guidelines for google-cloud-cpp

`google-cloud-cpp` provides idiomatic C++17 client libraries for Google Cloud
Platform services. Over 160 libraries under `google/cloud/` are generated by the
in-repo GAPIC micro-generator (`generator/`), while core runtime components and
several flagship data-plane libraries (`bigtable`, `storage`, `pubsub`,
`spanner`, and `bigquery/v2/minimal`) contain hand-crafted or hybrid code with
directory-specific `AGENTS.md` files.

## Architecture and Public API Boundaries

- **Layered Call Flow (`ARCHITECTURE.md`):**
  1. **`*Client`:** Thin, copyable, value-semantic public facade taking a
     `std::shared_ptr<*Connection>`.
  1. **`*Connection`:** Virtual public interface (`mocks/mock_*_connection.h`
     provides `Mock*Connection` for application tests). `*ConnectionImpl` owns
     retry loops, LRO polling (`future<StatusOr<T>>`), and pagination
     (`StreamRange<T>`).
  1. **`*Stub` (`internal/`):** Internal gRPC/REST interface wrapped by a
     decorator stack (`Auth` -> `Metadata` -> `Logging` -> `TracingStub` -> raw
     stub, plus optional `RoundRobin`).
- **Public API Stability (`doc/public-api.md`):**
  - Public symbols live only in `google::cloud`, `google::cloud::mocks`,
    `google::cloud::<lib>[_<subpath>_v<N>]`, and `*_mocks`, declared in headers
    matching `google/cloud/*.h`, `google/cloud/<lib>/*.h`,
    `google/cloud/<lib>/<service_dir>/*.h`, or `.../mocks/*.h`.
  - **Never** expose `internal` or `*_internal` types in public signatures, not
    even via `using` / `typedef` aliases.
  - Experimental additions to GA libraries **must** require callers to spell
    `experimental` / `Experimental` (`google::cloud::ExperimentalTag` parameter,
    `*_experimental` namespace, `Experimental*` name, or `experimental-*` build
    target).
  - Patch releases are ABI-compatible (`GOOGLE_CLOUD_CPP_NS` is
    `v<MAJOR>_<MINOR>` with no patch component).
- **Configuration via `google::cloud::Options`:**
  - Prefer `google::cloud::Options` over legacy custom option structs.
  - Populate defaults at the user-facing entry point (`*DefaultOptions()`),
    validate with `google::cloud::internal::CheckExpectedOptions<...>()`, and
    merge per-call options via `internal::OptionsSpan` +
    `internal::MergeOptions`.
  - Option precedence: environment variables > per-call `Options` > `*Client`
    constructor `Options` > `Make*Connection` `Options` > library defaults.
  - Do **not** duplicate server-side request validation on the client unless
    needed to prevent a local crash or undefined behavior.
- **Core Runtime Files:** When modifying top-level `google/cloud/*.{h,cc}`,
  `google/cloud/internal/`, `google/cloud/mocks/`,
  `google/cloud/universe_domain/`, `google/cloud/opentelemetry/`, or
  `google/cloud/testing_util/`, read `google/cloud/internal/AGENTS.md` for
  sub-target dependency boundaries.

## Generated vs. Hand-Crafted Code

- **Never Edit Generated Files Directly:**
  - Any file containing `Generated by the Codegen C++ plugin` is deleted and
    regenerated by `ci/cloudbuild/builds/generate-libraries.sh`. Modify
    `generator/` or `generator/generator_config.textproto` instead (see
    `generator/AGENTS.md`).
  - Do not hand-edit files marked `DO NOT EDIT -- GENERATED BY CMake` (`*.bzl`
    source lists), `protos/google/cloud/compute/v1/internal/*.proto`,
    `external/googleapis/protolists/*.list`,
    `external/googleapis/protodeps/*.deps`, or
    `ci/etc/expected_install_directories`.
- **Documentation & README Injection Markers:**
  - Do not manually edit content between `<!-- inject-...-start -->` and
    `<!-- inject-...-end -->` markers in `README.md` or `doc/*.dox` (updated by
    `ci/generate-markdown/`).
  - For generated GAPIC libraries,
    `doc/{environment-variables,options,override-*}.dox` and
    `<service_dir>/.repo-metadata.json` are overwritten on generator runs; only
    `BUILD.bazel`, `CMakeLists.txt`, `quickstart/*`, and `README.md` /
    `doc/main.dox` outside injection markers are hand-maintained.
- **GAPIC Unity Builds & Samples:**
  - `bazel/gapic.bzl` and `cmake/GoogleCloudCppLibrary.cmake` compile **only**
    `internal/*_sources.cc` amalgamation translation units for generated
    services. Handwritten samples added under `<service_dir>/samples/` must end
    in `*_samples.cc` to be picked up by both build systems.
  - When scaffolding or expanding a generated library, follow
    `.agents/skills/generate-library/SKILL.md` and
    `doc/contributor/howto-guide-adding-generated-libraries.md`.

## C++17 Style and Language Guidelines

Follow the
[Google C++ Style Guide](https://google.github.io/styleguide/cppguide.html),
`doc/cpp-style-guide.md`, and `.gemini/styleguide.md`:

- **Minimum Standard:** C++17. Keep abstractions simple and linear (return early
  to avoid unnecessary `else` blocks; omit braces on single-line `if` statements
  under 80 characters when there is no `else`).
- **East `const` & Pointer Alignment:** Place `const` to the right of what it
  modifies and `*`/`&` adjacent to the type (`std::string const& s`, `char* p`).
- **Include Guards:** Format as `GOOGLE_CLOUD_..._H` with **no trailing
  underscore** (checked by `ci/check-include-guards.gawk`).
- **License, Doxygen, and `TODO`s:**
  - New files require the Apache 2.0 header (`Copyright YYYY Google LLC`). Never
    alter the copyright year on existing or moved files.
  - Document all public APIs using Doxygen (`///` for single-line, `/** ... */`
    for multi-line, preferring `@param`/`@return` over `\param`).
  - Reference a GitHub issue in `TODO` comments: `// TODO(#12345) - ...`.
  - Deprecated functions should not have samples (`doc/adr/`); preserve their
    unit and integration tests until removal.

### Standard Library (`std`) vs. Abseil (`absl`) & SDK Vocabulary Types

Always use C++17 `std` vocabulary types and headers instead of Abseil polyfills
(unless required by an external/Abseil API signature), and use SDK concurrency
and outcome types:

| Do Not Use                                                                                                | Use Instead                                                                                         | Header                       |
| :-------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------- | :--------------------------- |
| `absl::optional`, `absl::nullopt`, `absl::make_optional`                                                  | `std::optional`, `std::nullopt`, `std::make_optional`                                               | `<optional>`                 |
| `absl::variant`, `absl::monostate`, `absl::visit`, `absl::get`, `absl::get_if`, `absl::holds_alternative` | `std::variant`, `std::monostate`, `std::visit`, `std::get`, `std::get_if`, `std::holds_alternative` | `<variant>`                  |
| `absl::any`, `absl::any_cast`, `absl::make_any`                                                           | `std::any`, `std::any_cast`, `std::make_any`                                                        | `<any>`                      |
| `absl::string_view`                                                                                       | `std::string_view`                                                                                  | `<string_view>`              |
| `absl::Mutex`                                                                                             | `std::mutex`                                                                                        | `<mutex>`                    |
| `absl::Status`, `absl::StatusOr`                                                                          | `google::cloud::Status`, `google::cloud::StatusOr`                                                  | `"google/cloud/status_or.h"` |
| `std::future`, `std::promise`                                                                             | `google::cloud::future`, `google::cloud::promise`                                                   | `"google/cloud/future.h"`    |

### Type Deduction and `auto` Guidelines (Abseil Tip #232)

Follow [Abseil Tip #232](https://abseil.io/tips/232): use `auto` only when it
makes code clearer or safer, not merely to avoid spelling a type.

- **Range-Based `for` Loops Over Maps:** Always use structured bindings
  (`for (auto const& [key, value] : map)`) over `std::map`,
  `absl::flat_hash_map`, protobuf maps, and JSON `.items()` to avoid implicit
  `std::pair` copies.
- **Factory Functions:** Allow `auto` when the type is explicit on the RHS
  (`auto client = std::make_shared<MockClient>();`,
  `auto ptr = std::make_unique<T>(...);`).
- **Iterators:** Allow `auto` for iterators only when the container is declared
  in local scope. For member/non-local containers, spell out the iterator or the
  dereferenced element type (`ElementType const& elem = *it;`).
- **Spell Out Domain Types, Protobufs, Return Types, and Primitives:**
  - Do not hide `StatusOr<T>`, domain types, or protobuf fields behind `auto`
    (write `StatusOr<ObjectMetadata> actual = client.InsertObject(...);`).
  - Use explicit integer/scalar types (`std::size_t`, `std::int64_t`, `bool`)
    rather than deducing from literals.
- **Explicit Qualifiers:** Always qualify with `const`, `&`, or `*`
  (`auto const&`, `auto&`, `auto*`) when not intentionally copying by value.

### Default Arguments in Internal Namespaces

- Functions, member functions, and constructors in `internal` namespaces
  (`google::cloud::*::internal`, `google::cloud::*_internal`) **must not**
  specify default parameter values. Callers and unit tests must pass all
  arguments explicitly; add an explicit overload if needed.

### Header Include Conventions

- **Local-to-Global Order (`.clang-format`):** Matching `.h` first, then project
  headers (`"google/cloud/..."`), external library headers, and C++/C standard
  headers last. Run `clang-format` rather than hand-sorting.
- **`googleapis` vs. `protobuf` Generated Headers:**
  - Always use **double quotes** (`"..."`) for `.pb.h` and `.grpc.pb.h` headers
    from `googleapis/googleapis` (e.g., `"google/api/client.pb.h"`,
    `"google/iam/v1/policy.pb.h"`, `"google/bigtable/v2/bigtable.grpc.pb.h"`).
  - Always use **angle brackets** (`<...>`) for upstream
    `protocolbuffers/protobuf` headers (e.g.,
    `<google/protobuf/field_mask.pb.h>`, `<google/protobuf/timestamp.pb.h>`,
    `<google/protobuf/descriptor.h>`) and `<grpcpp/grpcpp.h>` (never obsolete
    `<grpc++/...>`, and write `grpc::StatusCode::OK` instead of `grpc::OK`).

## Cross-Cutting Implementation Invariants

- **Inline Version Namespaces:** Wrap all declarations and definitions inside
  `google::cloud*` namespaces with `GOOGLE_CLOUD_CPP_INLINE_NAMESPACE_BEGIN` and
  `GOOGLE_CLOUD_CPP_INLINE_NAMESPACE_END` (`google/cloud/version.h`). Never use
  legacy `*_CLIENT_NS` or `GOOGLE_CLOUD_CPP_GENERATED_NS` macros.
- **Exception-Free Library Code (`-fno-exceptions`):** Library `.h`/`.cc` files
  must compile with `-DGOOGLE_CLOUD_CPP_ENABLE_CXX_EXCEPTIONS=OFF`. Never use
  raw `throw`, `try`, or `catch` in library code; call
  `google::cloud::internal::ThrowStatus(...)`, `ThrowInvalidArgument(...)`,
  `ThrowRuntimeError(...)`, etc. (`google/cloud/internal/throw_delegate.h`).
  Exceptions are permitted in `samples/`, `examples/`, and `benchmarks/`, and in
  tests via `testing_util/expect_exception.h` or
  `#if GOOGLE_CLOUD_CPP_HAVE_EXCEPTIONS`.
- **Async `Options` Propagation:** Before crossing thread or callback boundaries
  (`CompletionQueue` timers, async RPCs, `.then()` continuations), capture
  `auto opts = internal::SaveCurrentOptions();` and restore
  `internal::OptionsSpan span(opts);` inside the callback.
- **Deprecation & Win32 Macro Hygiene:**
  - Mark deprecated public APIs with `GOOGLE_CLOUD_CPP_DEPRECATED("...")` and
    suppress warnings in tests of deprecated APIs using
    `"google/cloud/internal/disable_deprecation_warnings.inc"`.
  - In headers declaring methods that collide with Win32 macros (e.g.,
    `DeleteFile`), include `"google/cloud/ports_def.inc"` after all `#include`s
    and `"google/cloud/ports_undef.inc"` at the end of the header.

## C++ Testing Guidelines

- Use `EXPECT_THAT` / `ASSERT_THAT` with gtest/gmock matchers (`testing::Eq`,
  `testing::HasSubstr`, `testing::IsEmpty`, `testing::NotNull`) rather than
  calling methods inside basic assertions.
- Use `IsOk()`, `IsOkAndHolds(...)`, and `StatusIs(...)` from
  `google/cloud/testing_util/status_matchers.h` for `Status` and `StatusOr<T>`,
  and `EXPECT_TRUE` / `EXPECT_FALSE` for plain boolean expressions.
- **Prefer Declarative Container Matchers Over Imperative Loops:** Avoid manual
  `for` loops and `bool found = false;` flags in tests. Use `testing::Contains`,
  `testing::Each`, `testing::ElementsAre`, `testing::UnorderedElementsAre`, and
  `testing::SizeIs`. Duplicate salient setup/expectations in tests when it
  improves readability.
- **Write Custom Matchers for Complex Objects and Protobufs:** Define custom
  matchers with `MATCHER_P` / `MATCHER_P2` and `ExplainMatchResult`, composed
  via `AllOf`, `AnyOf`, `Property`, and `Field`:
  ```cpp
  MATCHER_P(MetricType, matcher, "") {
    return ExplainMatchResult(matcher, arg.metric().type(), result_listener);
  }

  MATCHER_P2(HasMetricLabel, key, val_matcher, "") {
    auto const& labels = arg.metric().labels();
    auto it = labels.find(key);
    if (it == labels.end()) {
      *result_listener << "no metric label '" << key << "'";
      return false;
    }
    return ExplainMatchResult(val_matcher, it->second, result_listener);
  }

  EXPECT_THAT(recorded_metrics, Contains(AllOf(
      MetricType(HasSubstr("outstanding_rpcs")),
      HasMetricLabel("channel_pool_lb_policy", Eq("RANDOM_TWO_LEAST_USED")))));
  ```

## Build Systems, Verification, and Commits

- **CMake -> Bazel `.bzl` Sync**
  (`doc/contributor/working-with-bazel-and-cmake.md`):
  - When adding, removing, or renaming source/header/test files in core or
    hand-crafted libraries, **always update `CMakeLists.txt` / `*.cmake`
    first**; configuring CMake regenerates the corresponding `*.bzl` lists
    loaded by `BUILD.bazel`. Commit both changes together.
  - Preserve `# Do not sort: grpc++ must come last` comments in `BUILD.bazel`
    files so `buildifier` keeps link order intact.
- **Common Build & Test Commands:**
  - Unit tests (Bazel): `bazelisk test --test_tag_filters=-integration-test`
    `//google/cloud/<lib>/...` (append `--config=asan`, `--config=tsan`,
    `--config=ubsan`, or `--config=otel2` as needed).
  - Unit tests (CMake):
    `ctest --test-dir <build-dir> --output-on-failure -LE integration-test`
  - Formatters & static checkers (clang-format, cmake-format, buildifier,
    mdformat at 80 cols, typos, include guards, README/dox injectors):
    `GOOGLE_CLOUD_CPP_FAST_CHECKERS=1 ci/cloudbuild/build.sh -t checkers-pr`
  - Local CI triggers (`ci/cloudbuild/triggers/`):
    `ci/cloudbuild/build.sh -t clang-tidy-pr` and `check-api-pr` (with
    `GOOGLE_CLOUD_CPP_CHECK_API=<lib>`).
- **Commit Messages & PRs:**
  - Use Conventional Commits (`<type>(<scope>): <description>`) with types
    `feat`, `fix`, `docs`, `impl`, `refactor`, `cleanup`, `test`, `ci`, `chore`,
    keeping the summary line under 50 characters.
